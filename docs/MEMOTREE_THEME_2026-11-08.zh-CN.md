# 11 月 8 日：MemoTree 主题操作与对话记忆对接

## 目标与边界

主题树是组织层，原始记忆是独立数据层。主题的移动、拆分、重命名和删除仅改变组织结构或归属，不改写记忆正文、作用范围、状态和内容版本。旧 `topic` 字符串继续保留原有检索及版本语义；用户主题使用稳定 ID。主题目录保存在本地 SQLite 中，现有记忆默认未分类。

## 一、主题树

每个主题具有稳定 ID、名称和可空的 `parent_id`；空父节点表示根主题。允许任意层级，禁止自引用和形成循环；父节点必须存在。同一父节点下按首尾去空白、Unicode NFC 和小写规范检查重名，同一主题下的不同父节点不允许同名。主题操作包括创建、重命名、移动和删除。删除需预览影响数量；不删除原始记忆。删除含子主题的节点前需明确策略，避免静默删除子树。看板、选择器和图谱显示路径并支持子树浏览，筛选与作用范围、状态组合。

## 二、对话记忆流程

复用现有候选提取、必要性路由、去重、冲突、修订和审阅流程；主题推荐发生在路由之后，以合法的现有主题 ID 输出，无法确定或失败时保留未分类，不阻塞捕获。归类不接受候选或改变范围。重复观察加强现有记忆时保留原主题；修订候选优先继承目标主题，接受或撤销时不得丢失用户调整。记忆合并候选若源主题不同，须由用户选择或保持未分类。自动归类遵守现有学习开关、敏感候选审阅及拒绝规则；提交时重新校验主题和记忆的状态，避免覆盖用户并发更改。

## 三、主题摘要与层次检索

摘要是可重建的派生数据，记录源记忆 ID、内容版本、范围、生成状态及依赖；不取代原始记忆。内容、归属、状态、树结构变化后标记失效，后台按需刷新；过期摘要不能作为有效事实。摘要只从符合当前项目、会话、状态和排除规则的记忆生成或使用，敏感候选及已删除内容不可残留于摘要。先展示摘要和证据，再单独验证层次检索是否保持现有注入和权限边界；未完成前不改变对话注入。

## 四、子主题建议与审阅

只有主题积累足够多的相关有效记忆后才触发评估；数量阈值用于触发而不代表必须拆分。Agent 输出建议的子主题、拟归类条目和原因，用户可预览、调整、拒绝或接受。接受时检查版本与用户并发操作，事务写入；不修改原始记忆内容或自动接受候选。主题合并及复杂重组留待后续。

## 五、记录和撤销

所有 Agent 树结构操作记录操作 ID、主体、时间、前后结构与关联、来源和状态；复合操作事务提交。撤销必须校验当前状态仍与原操作结果一致，发现用户后续修改则提示冲突，不覆盖新操作。操作记录避免保留敏感记忆正文。与现有单条分类历史、内容回滚和敏感删除规则兼容。

## 实施与验收顺序

1. 主题树、父子操作、子树筛选、结构操作记录和安全撤销；迁移保留现有主题及归属。
2. 接入捕获路由与修订审阅：现有主题自动归类、失败降级、用户选择优先及并发校验。
3. 主题摘要和失效、范围隔离、隐私擦除；在验证可用前不接入注入。
4. 满足阈值后生成可审阅的子主题建议，接受或撤销为原子操作。
5. 分别验证旧库升级、刷新重启、并发、敏感候选、拒绝和恢复、跨项目隔离、导出回读及失败重试。手动检查主题树、筛选、图谱和审阅流程。
